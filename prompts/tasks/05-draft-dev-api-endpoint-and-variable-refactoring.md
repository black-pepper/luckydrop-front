# Task Type
- Development

## 1-1. Prompt File Name
- 작업 번호: 05
- 단계: `draft`
- 유형: `dev`
- 작업 슬러그: api-endpoint-and-variable-refactoring
- 최종 파일명: `05-draft-dev-api-endpoint-and-variable-refactoring.md`

## 2. Goal
- API 엔드포인트를 `admin`에서 `manage`로 변경하고, 초대 코드 관련 변수명을 `drawCode`에서 `invitationCode`로 통일한다.
- 추가된 API는 반영하지 않고 기존 연동된 API의 경로와 변수명만 수정한다.

## 3. Background
- Luckydrop API 명세가 업데이트되어 관리 기능의 기본 경로가 `/api/admin`에서 `/api/manage`로 변경됨.
- `contentCode`와 혼동을 피하기 위해 참가자용 초대 코드를 `invitationCode`로 명칭을 통일함.

## 4. Scope
### Include
- `src/api/client.ts`: `/api/admin/`이 포함된 모든 호출 경로를 `/api/manage/`로 변경.
- 프로젝트 전체: `drawCode`라는 명칭을 사용하는 변수, 프로퍼티, 파라미터를 `invitationCode`로 변경.
- API 통신 시 사용되는 DTO/인터페이스(`src/api/types.ts`)에서 초대 코드를 의미하는 필드명 확인 및 수정.

### Exclude
- OpenAPI 명세에 새로 추가된 API(예: `/api/manage/invitation-codes` 관련 CRUD)의 신규 구현.
- 기존에 동작하던 기능의 로직 변경 (명칭과 경로만 수정).

## 5. Constraints
- 모든 파일은 UTF-8로 저장.
- 기존 아키텍처와 디자인 시스템 유지.
- 변경 범위는 명칭 및 경로 수정으로 최소화.
- 수정 후 기존 관리자 페이지 및 사용자 뽑기 페이지의 동작 여부 확인.

## 6. Naming Plan
- API Path: `/api/admin/...` -> `/api/manage/...`
- Variable/Property: `drawCode` -> `invitationCode`
- 용어 통일: 초대 코드는 항상 `invitationCode`로 사용.

## 7. Deliverables
- `src/api/client.ts`, `src/api/types.ts` 수정 사항.
- `drawCode`를 사용하던 컴포넌트 및 페이지의 수정 사항.
- 수정 후 영향 범위 요약 보고.

## 8. Checks Before Execution
- 목표가 충분히 구체적인가: 예
- 제외 범위가 명확한가: 예 (신규 API 미반영)
- 이름이 기존 프로젝트 규칙과 충돌하지 않는가: 예 (invitationCode는 이미 일부 사용 중)

```md
- OpenAPI 명세에 포함된 새로운 엔드포인트(예: invitation-codes 관리 API)의 신규 연동 및 UI 개발.

- 기존의 API 호출 구조(fetch, authRequest 등)를 유지한다.
- `contentCode`는 변경 대상이 아님에 유의한다.
- 추가적인 리팩터링이나 기능 개선은 수행하지 않는다.

- API 경로: `/api/manage/contents`, `/api/manage/rewards` 등

- `src/api/client.ts`의 모든 `admin` 경로가 `manage`로 변경됨.
- 코드 내에 `drawCode`라는 명칭이 남아있지 않음 (주석 제외).
- 기존의 관리자 페이지와 사용자 뽑기 페이지가 정상적으로 API를 호출함 (경로 변경 반영).
```
